# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a self-contained fork of the Refal-05 compiler - a Refal-5 subset compiler that compiles to C89. The key difference from the original distribution is that this fork is **self-contained** and does not require an external Refal-5 compiler for bootstrapping. Instead, it stores pre-compiled C artifacts from previous builds in the `bootstrap/` directory and uses them to rebuild the compiler with itself.

Refal-05 is written in itself (self-applying compiler), compiles to C89, and can be extended with custom C functions.

## Bootstrap Architecture

The compiler uses a multi-stage bootstrap process:

1. **Bootstrap artifacts**: Pre-compiled C files in `bootstrap/` directory generated from previous compiler build
2. **Stage 1**: Compile old compiler (`bin/refal05-old`) from bootstrap C files
3. **Stage 2**: Use old compiler to recompile Refal source files (`src/*.ref`) to generate new C files
4. **Stage 3**: Compile new compiler (`bin/refal05`) from newly generated C files
5. **Validation**: Run autotests to verify the new compiler works correctly

The bootstrap C files fall into two groups:

- **Regenerated on every bootstrap** (these have Refal sources in `src/`): `refal05c.c`, `R05-Parser.c`, `R05-Generator.c`, `R05-CompilerUtils.c`
- **Frozen vendored artifacts** (no Refal source in this repo, never regenerated by the bootstrap): `R5FW-Parser.c`, `R5FW-Parser-Defs.c`, `R5FW-Transformer.c`, `R5FW-Plainer.c`, `Platform.c`, `LibraryEx.c`

Runtime libraries live in `lib/` and are compiled from C directly, not generated: `Library.c`, `refal05rts.c`.

### Where generated `.c` files land

The compiler derives the output path by stripping everything up to the last directory separator, but `IsDirectorySeparator` in `bootstrap/Platform.c` recognizes **only `/`**, never `\`. The consequence is platform-dependent and easy to mistake for a typo:

- Linux: `bin/refal05 src/refal05c` writes `./refal05c.c` into the current directory, so `src/bootstrap.sh` collects it with `mv *.c bootstrap`
- Windows: `bin\refal05.exe src\refal05c` writes `src\refal05c.c` (the backslash is not stripped), so `src\bootstrap.bat` collects it with `move /Y src\*.c bootstrap\`

Do not "unify" those two collection commands - each is correct for its platform.

`bootstrap/Platform.c` is the POSIX-flavoured build on both platforms for the same reason: its `PathSeparator` returns `:`, so `R05PATH` is colon-separated even on Windows.

## Build Commands

### Linux/Unix

#### Initial Bootstrap

```bash
make bin/refal05
```

This will:

1. Create `c-plus-plus.conf.sh` from template if it doesn't exist
2. Run `src/bootstrap.sh` which performs the full 3-stage bootstrap
3. Run all autotests

The bootstrap script (`src/bootstrap.sh`):

1. Sources `c-plus-plus.conf.sh` for C compiler configuration (defaults to gcc)
2. Builds `bin/refal05-old` from existing `bootstrap/*.c` files
3. Uses `refal05-old` to regenerate `bootstrap/*.c` from `src/*.ref`
4. Builds final `bin/refal05` from new `bootstrap/*.c` files
5. Runs `autotests/run.sh`

#### Testing

```bash
./autotests/run.sh

./autotests/run.sh arithmetic-32-bit.ref bad-comment.BAD-SYNTAX.ref
```

### Windows

#### Initial Bootstrap

```cmd
make bin/refal05.exe
```

Or directly:

```cmd
src\bootstrap.bat
```

The bootstrap script (`src\bootstrap.bat`):

1. Calls `c-plus-plus.conf.bat` for C compiler configuration (must be configured manually)
2. Builds `bin\refal05-old.exe` from existing `bootstrap\*.c` files
3. Uses `refal05-old.exe` to regenerate `bootstrap\*.c` from `src\*.ref`
4. Builds final `bin\refal05.exe` from new `bootstrap\*.c` files
5. Runs `autotests\run.bat`

**Note**: `make bin/refal05.exe` copies `c-plus-plus.conf.bat` from the template automatically, but the copied template contains no active compiler - it aborts with `C++ compiler is not selected` until you uncomment a compiler section. Edit it (Visual C++, MinGW, Clang, Borland, Watcom) before running bootstrap.

#### Testing

```cmd
autotests\run.bat

autotests\run.bat arithmetic-32-bit.ref bad-comment.BAD-SYNTAX.ref
```

### Common Features

The test scripts:

- Can be run from any directory (automatically find project root)
- Automatically detect test types based on filename suffix
- Tests with `.BAD-SYNTAX.ref` expect compilation to fail with error (not crash with exit code >= 200)
- Tests with `.SATELLITE.ref` are helper modules (automatically compiled with main test)
- Show pass/fail summary at the end

### Cleanup

```bash
make clear
```

Removes generated `*.c` files from project root.

## Key Directories and Files

- `src/` - Refal-05 compiler source code (written in Refal):
  - `refal05c.ref` - Main compiler entry point
  - `R05-Parser.ref` - Parser module
  - `R05-Generator.ref` - C code generator
  - `R05-CompilerUtils.ref` - Compiler utilities
  - `bootstrap.sh` / `bootstrap.bat` - Bootstrap build scripts
  - `c-plus-plus.conf.sh.template` / `c-plus-plus.conf.bat.template` - C compiler configuration templates
  - `benchmark.sh` / `benchmark.bat` - Benchmarking scripts, driven by `benchmark.prj` (note: `benchmark.prj` still lists `LibraryEx.ref`, which does not exist in `src/` - these scripts are upstream leftovers and are not exercised by CI)

- `bootstrap/` - Pre-compiled C artifacts from previous build (enables self-contained bootstrapping)

- `lib/` - Runtime and standard library:
  - `refal05rts.c/h` - Runtime support
  - `Library.c` - Built-in Refal functions (Prout, etc.)
  - `Go.c` - Aliases entry point `GO` to `Go`; **not linked** by any build or test script, so `$ENTRY GO` is the only entry point that actually works in this repo

- `autotests/` - Compiler test suite
  - `run.sh` / `run.bat` - Test runners (can run from any directory)
  - `*.ref` - Test programs
  - `*.BAD-SYNTAX.ref` - Expected compilation failures
  - `*.SATELLITE.ref` - Helper modules for tests
  - `nested-comment.BAD-SYNTAX._ref` - Disabled test; the `._ref` extension keeps it out of the `*.ref` glob

- `docs/` - Russian language documentation, published via GitHub Pages (`docs/_config.yml`):
  - `1-intro.md` through `5-implementation.md`, `A-style-guide.md` - Language and implementation reference
  - `toc.js` - Table of contents for the published site

- `examples/` - Sample programs:
  - `lambda.ref` - Standalone Refal example
  - `filesize-test.ref` + `filesize.c` - Example of extending Refal-05 with a custom C function

- `bin/` - Compiled binaries (created during build, gitignored)
  - `refal05` / `refal05.exe` - Final compiler executable
  - `refal05-old` / `refal05-old.exe` - Intermediate compiler from bootstrap

- `c-plus-plus.conf.sh` / `c-plus-plus.conf.bat` - C compiler configuration (created from template, not tracked in git)

## C Compiler Configuration

### Linux/Unix

The config file `c-plus-plus.conf.sh` is created from `src/c-plus-plus.conf.sh.template` if it doesn't exist.

Default configuration:

```bash
export R05CCOMP='gcc -Wall -g -DR05_POSIX -DR05_CLOCK_SKIP=20'
```

Important flags:

- `-DR05_POSIX` - Required on POSIX systems for correct `System` function behavior
- `-DR05_SHOW_STAT` - Show compiler statistics (used in bootstrap.sh)
- `-DR05_CLOCK_SKIP=20` - Clock configuration for performance monitoring

### Windows

The config file `c-plus-plus.conf.bat` is copied from `src/c-plus-plus.conf.bat.template` by `make bin/refal05.exe`, but unlike the Linux template it has **no default compiler** - every option is commented out and the script exits with an error until you uncomment one.

Options present in the template:

- **Visual C++**: `set R05CCOMP=cl /EHcs /W3 /wd4996` (plus a `vcvarsall.bat` call)
- **Borland C++ 5.5**: `set R05CCOMP=bcc32 -IC:\Borland\BCC55\Include -LC:\Borland\BCC55\Lib -w`
- **MinGW**: `set R05CCOMP=gcc -Wall -g`
- **Watcom**: `set R05CCOMP=cl -nologo -W3 -passwopts:-wcd=13` (plus an `owsetenv.bat` call)
- **Clang**: `set R05CCOMP=clang -Wall -g`

CI does not use the template at all: `.github/workflows/build.yml` writes its own `c-plus-plus.conf.bat` with `cl /TC /W3 /wd4996 /O2`, where `/TC` forces the sources to be compiled as C rather than C++.

## Compiler Usage

After building, the compiler is in `bin/refal05`. To compile a Refal program:

```bash
R05PATH=/path/to/repo/lib bin/refal05 hello refal05rts Library
```

This generates `hello.c` in the **current working directory** and (if `R05CCOMP` is set) an executable.

Required modules:

- `refal05rts` - Runtime support
- `Library` - Built-in functions (Prout, Put, Get, etc.)

`R05PATH` is mandatory here: `refal05rts` and `Library` are resolved as bare module names, and their `.c` files live in `lib/`, which the compiler does not search by default. Without it the run fails with `COMMAND LINE ERROR: file refal05rts not found`. `R05PATH` is colon-separated on every platform (see `bootstrap/Platform.c`).

The bootstrap and test scripts sidestep this by passing explicit paths (`./lib/Library ./lib/refal05rts` in `src/bootstrap.sh`) or by handing the runtime `.c` files straight to the C compiler (`autotests/run.sh`).

## Source Code Structure

The compiler consists of four main Refal modules:

1. **refal05c** - Main driver that orchestrates compilation
2. **R05-Parser** - Parses Refal source code into AST
3. **R05-CompilerUtils** - Shared utilities for compilation
4. **R05-Generator** - Generates C code from AST

These depend on R5FW (Refal-5 Framework) libraries which are vendored in `bootstrap/`.

## Modifying the Compiler

When modifying compiler source files in `src/*.ref`:

1. Make changes to `.ref` files
2. Run `make bin/refal05` or `src/bootstrap.sh` to rebuild
3. This will:
   - Use old compiler to compile your changes
   - Replace the four regenerated files in `bootstrap/` (`refal05c.c`, `R05-Parser.c`, `R05-Generator.c`, `R05-CompilerUtils.c`) with newly generated C; the vendored R5FW files are left untouched
   - Build new compiler from those files
   - Run tests to validate

The regenerated `bootstrap/*.c` files are **committed** - they are the seed for the next build, so a source change is only complete once the updated C artifacts are committed alongside it.

If bootstrap fails, you may need to manually fix `bootstrap/*.c` files or revert changes.

## CI/CD

GitHub Actions workflow (`.github/workflows/build.yml`) automatically:

- Triggers on pushes to `master` branch, pull requests targeting `master`, and manual `workflow_dispatch` runs
- Builds the compiler on **both Linux and Windows** in parallel

### Linux Build Job

- Runs on Ubuntu with GCC
- Executes `make bin/refal05` (full bootstrap with tests)
- Uploads `bin/refal05` as `refal05-linux` artifact (90 days retention)
- Uploads `bootstrap/` as `bootstrap-artifacts-linux` artifact (90 days retention)
- On failure: uploads `autotests/__error.txt` as `test-errors-linux` artifact (30 days retention)

### Windows Build Job

- Runs on Windows with MSVC (Visual C++)
- Writes its own `c-plus-plus.conf.bat` with `cl /TC /W3 /wd4996 /O2` rather than using the template
- Locates `vcvars64.bat` through `vswhere.exe` instead of a hardcoded Visual Studio path; the `windows-latest` image changes its Visual Studio version over time, so never hardcode that path again
- Executes `src\bootstrap.bat` (full bootstrap with tests)
- Uploads `bin\refal05.exe` as `refal05-windows` artifact (90 days retention)
- Uploads `bootstrap\` as `bootstrap-artifacts-windows` artifact (90 days retention)
- On failure: uploads `autotests\__error.txt` as `test-errors-windows` artifact (30 days retention)

Artifacts can be downloaded from the Actions tab on GitHub after each build.

## Code Style

**Shell scripts**:

- Do not use inline comments in bash scripts (`.sh`)
- Do not use inline comments in batch scripts (`.bat`)
- Keep scripts clean and simple like the bootstrap and test scripts
- Bash: Use `set -ex` for bootstrap scripts and `set -e` for test scripts to distinguish script errors from expected failures
- Batch: Use `setlocal enabledelayedexpansion` and proper error checking with `errorlevel`

## Important Notes

- The language is **Refal-05**, not full Refal-5 (subset with some differences in metafunctions, no long arithmetic)
- Entry point is always `$ENTRY GO`; `lib/Go.c` would also allow `$ENTRY Go`, but nothing links it
- All source files use UTF-8 encoding
- Some tests are **expected to fail** (those with `.BAD-SYNTAX.ref` suffix) - the compiler should reject them with exit code < 200
- Config files (`c-plus-plus.conf.sh` / `c-plus-plus.conf.bat`) are created at project root and should not be committed to git (both are in `.gitignore`, alongside `bin` and `src/cfiles`)
- The project supports both **Linux/Unix** and **Windows** platforms with parallel scripts
- Prebuilt Unix and Windows binaries are published as GitHub releases; the release tag matches the last upstream commit merged into this fork
- Compiler sources in `src/` are kept in sync with upstream Refal-05 and are deliberately left unmodified apart from an MSVC fix, so prefer changing build scripts over changing `src/*.ref`
