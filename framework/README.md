# Вендорённые исходники Рефал-5-фреймворка

Здесь лежат исходники [Рефал-5-фреймворка](https://github.com/Mazdaywik/refal-5-framework), от которого зависит компилятор.
Они скопированы без изменений и не редактируются: правки отправляются в оригинальный репозиторий.

Зафиксированная версия указана в файле `PINNED-COMMIT`.

| файл                   | откуда взят                |
| ---------------------- | -------------------------- |
| `LibraryEx.ref`        | `lib/LibraryEx.ref`        |
| `R5FW-Parser.ref`      | `lib/R5FW-Parser.ref`      |
| `R5FW-Plainer.ref`     | `lib/R5FW-Plainer.ref`     |
| `R5FW-Transformer.ref` | `lib/R5FW-Transformer.ref` |
| `Platform.ref`         | `lib/posix/Platform.ref`   |
| `LICENSE`              | `LICENSE`                  |

`Platform.ref` взят в POSIX-варианте намеренно, в том числе для сборки под Windows: его `PathSeparator` возвращает `:`, поэтому `R05PATH` разделяется двоеточиями на всех платформах.

## Зачем это здесь

Раньше в `bootstrap/` лежали замороженные C-файлы, сгенерированные из этих исходников когда-то и никогда не перегенерируемые.
Это означало, что форк таскает устаревшие двоичные артефакты чужого проекта: их нельзя было пересобрать, не имея внешнего Рефала-5, и они постепенно расходились с фреймворком.

Оказалось, что этого не требуется: компилятор Рефала-05 сам компилирует исходники фреймворка, как и в оригинальной сборке (`src/makeself.sh`).
Поэтому исходники лежат здесь, а раскрутка генерирует из них C наравне с модулями компилятора.
Теперь весь каталог `bootstrap/` воспроизводится из исходников, замороженных артефактов не осталось.

## Как поднять версию

```bash
git clone https://github.com/Mazdaywik/refal-5-framework /tmp/r5fw
git -C /tmp/r5fw rev-parse HEAD > framework/PINNED-COMMIT
cp /tmp/r5fw/lib/{LibraryEx,R5FW-Parser,R5FW-Plainer,R5FW-Transformer}.ref framework/
cp /tmp/r5fw/lib/posix/Platform.ref framework/
cp /tmp/r5fw/LICENSE framework/
make bin/refal05c
```

Раскрутка должна пройти и выйти на неподвижную точку.
Если она падает, значит фреймворк изменил интерфейс, которым пользуется компилятор, и требуется разбирательство, а не автоматическое обновление.
Поэтому версия фреймворка поднимается вручную и осознанно, а не по расписанию: смена фреймворка меняет внутренности компилятора, в отличие от обновления из апстрима Рефала-05.
